# 학교 무상급식 관리대장

제공한 관리대장과 정기 지출·징수 자료를 **하나의 월별 대장**에서 확인합니다. 별도의 ‘첨부/작업 대장’ 선택이나 가져오기 작업이 필요하지 않습니다.

## 현재 반영 자료
- 관리대장: 학교 무상급식 관리대장_2026학년도_2026.10.13.xlsx
- 실제 지출: 지출실적조회(지출결의)_20261016.xlsx
- 실제 징수·수납: 징수부_20261016.csv
- 적용: 2026년 3~9월은 제공 자료 기준 실적, 10~다음 해 2월은 원본 함수의 예상 분기
- 3~9월도 월 마감·회계 확정까지 인증한 의미가 아닙니다. 제공 자료 조회 시점의 지급확정·징수·수납 집계입니다.

## 계산 기준
월 순서는 3월~12월 → 다음 해 1·2월 → 연간 합계로 고정합니다.

- 학생 재료비·운영비: 학년별 학생수 × 월별 급식일수 × 1식 단가. 2026학년도 단가 4,670원·540원. 원본 3월 보정액은 보존합니다.
- 월별 학생수 미입력 시 최근의 직접 입력/정산 인원을 이후 빈 달에 적용합니다. 기본 학생수·급식일수는 제공 관리대장에 연결하며 2월 0일도 보존합니다. 기본값·예상값을 실제 입력값으로 복사 저장하지 않아 다음 자료 갱신 시 기준을 교체할 수 있습니다.
- 식재료 예상 지출: 원본 함수의 도/시 72%·28% 및 수익자 식재료비 참조. 운영비·자체부담 비용: 원본 IF 함수의 월별 정액 가정. 지원금 재원 구분은 사용자가 확인한 식재료비 교육청 72%·안산시 28%, 운영비 교육청 100%·안산시 0%를 적용합니다.
- 인건비: 연간 총액 318,588,000원, 월별 계획배분은 원본 기준. 실제 교부시점과 구분합니다.
- 교직원 식재료 4,733원(쌀지원금 포함), 운영 540원, 인건비+부가세 957원. 원본 전반기 10원 절사 방식 보존.
- 무상급식 월별 산정행은 분기 교부총액으로 대체하거나 비우지 않습니다. 분기 교부액·분기 총액 정산 변경은 신청 화면의 별도 비교 기록입니다. 월별 정산 수정액과 대장 셀 수정액은 보존·우선 적용합니다.

## 학사일정 · 월별·학년별 날짜 연결
- ‘학생수·분기 신청 → 분기 신청·정산·실제 교부’의 상단에서 월을 고르면, 1일~말일을 가로로 펼친 날짜/요일 표와 1·2·3학년 행을 봅니다. 아래 학생수 표의 각 월 ‘일정’ 버튼으로도 바로 이동합니다.
- 날짜별 `1=급식 / 0=미급식`을 눌러 변경하고 학년별 일수를 자동 합산합니다. 학년과 기간을 지정한 일괄 변경, 날짜별 공통 학사일정 메모, 긴 메모 전체 보기·수정을 지원합니다. 메모만 입력해도 급식 여부가 자동 변경되지는 않습니다.
- 학년별 ‘일수 적용’을 켠 달만 일정 합계를 계산에 사용합니다. 월별 학생수 × 일정 일수 → 학생 식수 → 식재료·운영비와 교육청/안산시 산정액으로 연결됩니다. 아래 일수 입력칸은 적용 중 잠기며 일정 일수가 표시됩니다.
- 기존 직접 입력/신청 일수를 덮어쓰지 않습니다. 일수 적용을 끄면 기존 일수로 복귀합니다. 실제 학생 정산 식수, 월별 금액 정산 변경, 대장 셀 변경액의 우선순위는 그대로이며 실제 교부액을 덧셈하거나 다시 생성하지 않습니다.
- 교직원 65명 자동 예상도 연결된 학년별 일수 중 최댓값을 사용합니다. 직접 입력한 교직원/외부인 총식수(0 포함)는 유지됩니다. 학년별 일정이 완전히 다르면 실제 교직원 총식수를 직접 입력하세요.
- 원본 `기초자료!BK4:CS63`의 가로 날짜 배치와 `CR5=SUM(BM5:CQ5)`, `CS5=BL5*SUM(BM5:CQ5)`를 확인했습니다. 공개 코드에는 학년별 날짜의 0/1 집계 표시만 포함하며 개인 명단·원본 파일은 넣지 않습니다.
- 2026학년도 원본 날짜별 표시의 합계는 모든 기존 월별 급식일수와 일치합니다. 그러나 날짜 머리글의 실제 연도는 2025년 3~12월·2026년 1~2월이며, 일부 월 표시도 셀의 실제 날짜와 다릅니다. **자료 자체를 전학년도 자료로 재분류하지 않습니다.** 일자별 배치를 참고 표시하되 최초에는 계산 연결을 모두 끕니다. 화면 날짜/요일은 선택 학년도에 맞게 생성하며, 월별 일정 확인·수정 후 학년별 일수 적용을 선택합니다. 공휴일·방학·주말을 임의 추정/제외하지 않습니다.
- 다른 학년도에는 원본 날짜 표시를 복사하지 않고 빈 일정으로 시작합니다. 3월~다음 해 2월 순서, 실제 월 말일, 윤년을 검증합니다. 통합 저장·JSON 백업/복원·변경 이력에 일정과 메모를 함께 보존하며, 브라우저 저장/공유 제한은 기존과 같습니다.

## 분기 신청·정산·실제 교부 통합 표
- 4개 분기를 유지하며 각 분기 안의 월별·학년별 학생수를 한 표에 입력합니다. 기존 분기 공통 인원은 각 월의 기본값으로 보존하며 월별 입력을 저장하면 해당 월 값이 우선합니다. 월별 급식일수와 식수·지원금을 같은 행에서 확인하며 입력 즉시 계산합니다.
- 학생수·일수 모두 3월~다음 해 2월 순서의 12행×3열의 엑셀 붙여넣기를 지원합니다. 분기 합계와 연간 합계도 자동 계산합니다.
- 신청 표는 식재료비 교육청 72%·안산시 28%, 운영비 교육청 100%로 구분합니다. 소수 둘째 자리까지 표시하고 임의 원 단위 절사는 하지 않습니다.
- 실제 교부액은 분기·재원·항목별 표에 별도로 입력합니다. 최초 금액과 변경 후 총액·사유를 보존합니다. 이전 합산 교부액은 임의 재원 분할 없이 보존하며, 일부 재원만 입력되면 합산액을 미확정으로 유지합니다.
- 별도 ‘월별 인원·정산 수정’ 탭을 없애고 공통 학생수·급식일수 입력으로 통합했습니다. 월별 직접 입력이 있으면 기존 신청값보다 우선 표시하며, 둘이 다른 기존 신청 기준은 읽기 전용으로 보존합니다. 공통 입력에서 항목을 수정하면 신청·월별 입력을 함께 갱신하고 변경 이력을 남깁니다. 저장할 때 직접 입력된 기존 신청 인원·일수도 월별 공통 입력에 연결하되 자동 예상·기본값은 실제 입력값으로 복사하지 않습니다.
- 정산 인원·사유는 표 오른쪽 해당 월의 ‘정산 수정’을 펼쳐 입력합니다. 정산값이 우선 적용되며 지우면 공통 입력·최근 인원 자동 예상으로 돌아갑니다. 실제 정산 식수·금액 수정과 분기 교부 기록도 보존합니다. 실제 교부액을 월별 수입으로 중복 반영하지 않습니다.

## 실적 집계
- 지출: 지급확정 행 중 원본 대장의 산출내역과 일치하는 행을 합산합니다. 제목의 첫 ‘월’ 앞 2자를 해석하는 원본 방식으로 급식 대상월을 구하고, 없으면 확정일자의 월을 사용합니다. 같은 날짜·번호라도 산출내역별 상세행이므로 임의 중복 제거하지 않습니다.
- 징수부: 적요에 교직원이 포함된 날짜 명세만 사용합니다. 머리말·본예산·합계·반복 제목은 제외하고 적요의 급식 대상월로 합산합니다. 거래일자의 월과 혼동하지 않습니다.
- 징수액/수납액/불납결손액을 분리하며 미납액은 실적월에만 징수−수납−불납결손으로 계산합니다. 원본 CSV의 중간 누적 미수납액을 다시 더하지 않습니다.
- 예상월 징수액은 교직원 예상 식수×단가입니다. 실제 수납은 자료에 있는 값만 반영하며 미래 예상 징수를 현금 수납으로 처리하지 않습니다. 예상월 미납액은 미확정입니다.
- 대장에 대응 행이 없는 영양사 인건비 등은 무상급식/수익자 지출에 임의 합산하지 않습니다. 학교 자체부담 지출도 별도 구분합니다.

## 정기 갱신과 저장
새 지출실적조회·징수부를 제공하면 대상월·항목을 검증하고 실적 집계를 갱신하여 배포합니다. 자료가 아직 없는 월은 원본 수식 예상치를 유지합니다. 사용자가 접속하지 않아도 외부 회계시스템을 자동 조회하는 기능은 아닙니다.

기존 브라우저의 학생수·일수·셀 변경액·변경 이력은 보존합니다. 셀 변경액은 강조 표시되며 비우면 최신 자료/수식 기준으로 복귀합니다. 백업·복원과 CSV 내보내기를 지원합니다.

- 화면과 집계 기준은 GitHub Pages에 공개됩니다. 개인별 급여·직원 이름·계좌정보·원본 XLSX/CSV·비밀키는 포함하지 않습니다.
- 직접 입력값은 현재 브라우저 localStorage에만 저장됩니다. 두 사람의 직접 입력 공동 저장·로그인·동시 수정 방지는 별도 구현이 필요합니다.
- 관리 잔액은 산정·예상·배분을 포함하며 실제 통장 잔액이나 확정 반납액이 아닙니다.
- 다른 학년도에는 2026 원본을 이식하지 않습니다. 해당 학년도 자료가 필요합니다.

## 개발
`node build.cjs`로 단일 `index.html`을 생성합니다. 원본 JS/CSS를 바꿨다면 빌드 결과도 배포해야 합니다.

`node test.cjs && node test-ledger.cjs && node test-enrollment.cjs && node test-unified.cjs && node test-request.cjs && node test-staff.cjs && node test-grants.cjs`

`ledger-reference.cjs`는 원본 수식/집계 기준, `ledger-data.cjs`는 개인정보 없는 최신 자료 집계입니다. 내부의 이전 계산 함수는 백업 호환 테스트용으로 보존하지만 실제 화면은 `LedgerMatrix.unified` 한 경로만 사용합니다.

## 교직원·외부인 월별 식수 (2026-10 개선)
- 식수·지원금 산정 탭은 학생 입력 없이 교직원·외부인 월별 총식수(12개월 × 2열)만 관리합니다. 엑셀 붙여넣기, 즉시 미리보기, 전체 저장을 지원합니다.
- 지난달까지 직접 입력한 식수 또는 제공 자료의 실제 식수를 적용합니다. 당월부터 다음 해 2월까지는 교직원 65명 × 월별 급식일수로 예상하며, 직접 입력값(0 포함)이 우선합니다. 예상 인원은 설정에서 변경할 수 있습니다.
- 미래 예상 일수는 학생수·분기 신청의 해당 월 학년별 급식일수 중 최댓값입니다. 교직원 운영일수가 다르면 총식수를 직접 입력하세요. 예상값은 저장된 입력칸에 복사하지 않습니다.
- 외부인은 직접 입력한 식수만 교직원과 동일 단가로 계산합니다. 65명은 교직원에만 적용합니다. 2026년 기본 급식 단가는 6,230원/식입니다.
- 교직원+외부인 산정액을 대장 징수예상액 및 수익자 식재료비·운영비·인건비로 연결합니다. 징수부 실제 징수·수납·미납은 예상액으로 덮어쓰지 않습니다.
- 학생 지원금 단가·금액 정산 설정은 학생수·분기 신청 안으로 이동했습니다. 기존 학생 실제 총식수는 월별 정산 수정에서 확인·변경합니다.
- 학교 자체부담은 월별 반복 안내와 상단 별도 총액 카드를 제거하고, 표 마지막에 월별·연간 소계(파생 행 50)를 추가했습니다. 지원금 잔액과 중복 합산하지 않습니다.
- 추가 계산 검증: `node test-staff.cjs`.

## 실제 교부 입력 단일화
- 상단의 ‘교부내역 수기 입력’ 탭은 제거하고 학생수·분기 신청 → ‘분기 신청·정산·실제 교부’ 아래 통합 교부표로 결합했습니다. 입력은 한 번만 하고 교부 집계는 읽기 전용으로 봅니다.
- `records`만 실제 교부의 원본 저장소입니다. `calculation.planning`의 교부 필드는 같은 기록에서 파생하는 비교용 값으로, 별도로 더하거나 다시 이전하지 않습니다. 학생수로 계산한 월별 지원금은 실제 교부액으로 덮어쓰지 않습니다.
- 이전 백업은 최초 로드 시 통합합니다. 같은 금액·사유는 한 번만 사용하고, 서로 다른 기록은 두 원본을 보존한 채 ‘기존 값 대조’로 표시합니다. 사용자가 원본을 선택해 저장하기 전 해당 항목은 교부 집계·비교에서 제외됩니다. 나머지 정상 항목은 계속 집계합니다.
- 통합 전 학생수 탭 교부 및 수기 입력 원본은 `grantIntegration`에 읽기 전용으로 보존합니다. 통합은 재실행·백업 복원해도 중복되지 않습니다. 변경 이력 500건 제한과 별도로 원본을 보관합니다.
- 분기/월별 입력 방식, 비활성 방식의 금액, 최초액·변경 총액·사유, 실제 0원, 인건비·추가 항목을 유지합니다. 월별 미입력이 있으면 입력된 금액만 교부 집계에 더하되 분기 비교 합계는 미확정입니다.
- 기존 재원 미분리 식재료비는 임의 72:28 분할하지 않습니다. 재원별 교부 기록이 생기면 미분리 합산액은 제외·보존하여 중복 합산을 막습니다.
- 기존 사용자 지정 분기는 변경하지 않습니다. 고정 학생수 분기와 자동 연결하지 않고 같은 학생수 탭에서 기존 교부 입력을 계속 관리합니다.

## 정기 제공 파일의 학년도 원칙
- 사용자가 제공하는 지출실적조회·징수부는 **내보내기 단계에서 선택한 해당 학년도 자료**입니다. 달력 연도나 1·2월 거래일만으로 전학년도 자료라고 추정해 제외하지 않습니다.
- 정기 제공 범위는 1월 1일~조회일 누적본입니다. 다음 갱신 때 이전 누적 총액에 추가하지 않고 해당 학년도 최신 누적 자료로 재검증·재산정해야 합니다. 상세행이 서로 같은 날짜·번호를 갖는다는 이유만으로 삭제하지 않습니다. 현재 앱이 업로드 파일을 자동 누적하는 기능을 제공하는 것은 아닙니다.


## 한국 공휴일·대체공휴일 표시
- 학사일정은 실제 달력 연도별 `holidays.cjs`의 검증된 날짜를 참조합니다. 현재 2026·2027년을 지원하므로 2026학년도(2026년 3월~2027년 2월) 전체가 포함됩니다. 공휴일 조회에 달력 연도를 쓰는 것은 사용자 자료의 학년도 분류를 바꾸는 것이 아닙니다.
- 공휴일 날짜 머리글은 빨간색과 ‘공휴/대체’ 텍스트로 구분하며, 표 위 목록에 날짜·전체 이름을 함께 표시합니다. 목록을 누르면 해당 날짜로 이동합니다. 주말은 기존 색으로 별도 표시합니다.
- 공휴일 표시는 읽기 전용 참고 정보입니다. 급식 0/1, 적용 체크, 직접 입력 일수, 정산액, 교부액, 메모 및 백업을 자동 변경하지 않습니다. 주말·공휴일을 일괄 미급식 처리하지도 않습니다.
- 음력 명절·대체공휴일은 검증된 날짜를 명시해 두며 임의 계산하지 않습니다. 2026년 9월 28일(추석 토요일 중복)과 6월 8일(현충일 토요일 중복) 등은 대체공휴일로 만들지 않습니다.
- 2026년 5월 1일 노동절·7월 17일 제헌절 공휴일 추가와 6월 3일 전국동시지방선거를 포함합니다. 2027년 2월 6~8일 설 연휴 및 2월 9일 대체공휴일도 포함합니다.
- 내장 데이터이며 실시간 API 조회가 아닙니다. 지원하지 않는 달력 연도는 ‘자료 미반영’ 경고를 보여주며 공휴일이 없는 해라고 오인하게 하지 않습니다. 이후 추가되는 임시공휴일·법 개정은 공식 자료 확인 후 데이터/앱을 갱신해야 합니다.
- 근거: [2026년 월력요항](https://www.kasi.re.kr/kor/publication/post/newsMaterial/32031), [2027년 월력요항](https://www.kasa.go.kr/prog/plcyBrf/brief/kor/sub01_01_04/view.do?plcyBrfNo=431), [노동절·제헌절 공휴일 지정](https://www.mpm.go.kr/mpm/comm/newsPress/newsPressRelease?boardId=bbs_0000000000000029&cntId=4250&mode=view). 2027년 부처님오신날은 [날짜 교차 확인](https://publicholidays.co.kr/ko/buddhas-birthday). 앱의 ‘공휴일 표시 기준’에서도 근거 링크를 확인할 수 있습니다.
- 검증: `node test-holidays.cjs` 및 기존 계산/통합 교부/학사일정 회귀 테스트. 공휴일 탐색·표시 자체로 기존 데이터나 계산 결과가 변하지 않는지 UI 검증합니다.
